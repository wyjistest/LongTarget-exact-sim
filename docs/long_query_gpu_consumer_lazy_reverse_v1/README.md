# Long-query exact reverse audit v1

This audit implements the bounded sequence for deciding whether a compact
canonical-reverse CUDA kernel is worth building:

1. host-only lazy reverse shadow;
2. two-window selection/reason differential gate;
3. real promoter shard reverse-set and weighted-work audit;
4. exact forward-only CUDA floor timing;
5. compact reverse implementation only if the projected end-to-end speed is at
   least 1.5x.

The audit does not change the default all-reverse endpoint path. The lazy path
is enabled only with
`FASIM_LONG_QUERY_GPU_CONSUMER_LAZY_REVERSE_SHADOW=1`, and it fails closed if
the selected attempt indexes or per-attempt reasons differ from the full
canonical consumer.

The host proof requested 2,306 reverse attempts (25.00% by count and
32.278958% by the endpoint-cell proxy). Selected indexes and reasons matched

## Forward-only floor

The diagnostic API
`prealign_cuda_find_max_forward_endpoints_batch()` uses the same byte8-first,
word16-on-overflow forward endpoint implementation as the exact path and
omits only the reverse-start score pass. It is not a canonical output mode.
On the real promoter shard, using the same measured CPU authority:

| path | wall seconds | speedup vs CPU |
| --- | ---: | ---: |
| CPU authority | 361.63 | 1.000x |
| all-reverse exact | 336.78 | 1.073787x |
| exact forward-only floor | 275.61 | 1.312108x |
| lazy-reverse projection | 299.55246 | 1.207234x |

The projection is:

```text
forward_wall + (all_reverse_wall - forward_wall) * lazy_cell_fraction
275.61 + (336.78 - 275.61) * 0.3914085769 = 299.55246 s
```

The 1.5x target permits at most `361.63 / 1.5 = 241.08667 s`. The measured
forward-only floor is already slower than that budget, before any compact
reverse work is added. Therefore:

```text
compact_reverse_kernel_authorized = false
full-output exact GPU acceleration = performance_no_go
```

This is a stop decision for the current exact full-output architecture, not a
claim that the scoped forward-only/top-k path is invalid. The existing scoped
screening path remains a separate contract and must not be reported as full
canonical output.

## Reproduction and tests

The read-only aggregation command is:

```bash
python3 scripts/summarize_long_query_lazy_reverse_shadow.py \
  --consumer-report .tmp/lazy-reverse-shadow/shard-0009/consumer.tsv
```

The floor and decision gate are generated by:

```bash
python3 scripts/assess_long_query_exact_reverse_floor.py \
  --lazy-summary .tmp/lazy-reverse-shadow/shard-0009/lazy-summary.json \
  --forward-report .tmp/lazy-reverse-shadow/shard-0009-forward-only/consumer.tsv \
  --forward-time .tmp/lazy-reverse-shadow/shard-0009-forward-only/time.txt \
  --all-reverse-time .tmp/lazy-reverse-shadow/shard-0009/time.txt \
  --cpu-time <frozen-cpu-time.txt> \
  --forward-output <forward-output> \
  --cpu-output <cpu-output> \
  --output docs/long_query_gpu_consumer_lazy_reverse_v1/audit.json
```

The deterministic host proof and CUDA endpoint regression are run with:

```bash
make check-fasim-lazy-reverse-shadow
make check-prealign-cuda-attempt-endpoint
python3 -m py_compile \
  scripts/summarize_long_query_lazy_reverse_shadow.py \
  scripts/assess_long_query_exact_reverse_floor.py
```

The measured receipts were produced from base source commit
`ab74ed9e989f96180ff23953e61b954ab57975d8`; the measured binary digest was
`78ae50642b90781004d59958ae8c4d1ed4116f0e5cc4e71dc51b94e29595369d`.
The later local rebuild is a separate binary and is not silently substituted
for the measured receipt.

No compact reverse CUDA kernel is included in this epoch.
